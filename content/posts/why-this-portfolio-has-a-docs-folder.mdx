Most portfolios start with `npx create-next-app` and a vibe. This one started
with a `docs/` folder.

Before the first component existed, the repo had a locked product-discovery
document, a functional specification with 47 numbered requirements, six
technology decision records, and a brand board signed off in an interactive
artifact. Overkill for a personal site? That's the point — **the portfolio is
itself the work sample**, and the process is part of the proof.

## The shape of the system

Every release moves through the same forward-only pipeline:

```text
Product Discovery (lock scope) → FSD (build gate) → Tech Discovery
  → ADRs → Implementation features (TDD) → Code → Release
```

Nothing gets built that doesn't trace back to a locked decision. The
functional spec pins measurable budgets — Lighthouse ≥ 90 on mobile,
WCAG 2.2 AA, reduced-motion parity — and the definition of done validates
them against the production deployment, not localhost.

## What that looks like in code

Take the accent switcher in the header. It's four buttons, but its contract
was written as requirements first, and its tests were written before the
implementation:

```ts
// The DOM attribute is the store — hydration-safe, no state duplication.
export function setAccent(accent: Accent): void {
  document.documentElement.dataset.accent = accent;
  try {
    window.localStorage.setItem(ACCENT_STORAGE_KEY, accent);
  } catch {
    // Storage unavailable — the switch still applies for this page view.
  }
}
```

The `try/catch` isn't defensive noise: "storage unavailable" is a numbered
edge case in the spec, with a test asserting the visual switch survives it.

## Why bother

Three reasons, honestly held:

1. **Senior engineering is mostly deciding, not typing.** A repo that shows
   the deciding — options weighed, budgets set, scope cut — says more than
   another todo app.
2. **Docs-first is faster at the finish.** Every feature here was implemented
   against a plan with test cases already written. No thrash.
3. **It compounds.** v2 of this site starts from a locked v1 baseline, not
   from archaeology.

## The 1.0.0 build, by the numbers

The loop that built this site ran the same protocol thirteen times:
validate → plan with test cases → branch → tests first → implement →
verify → merge. The receipts:

- **1 locked product discovery** (13 decisions) and **1 locked FSD**
  (47 requirements, 23 edge cases, measurable budgets)
- **7 ADRs** — framework, styling/motion, content pipeline, AI
  abstraction, contact delivery, analytics, brand identity
- **12 implementation features**, each `draft → ready → in-progress →
  done` with tests written before code
- **109 tests** at launch, plus lint and a static production build
  gating every merge
- **1 provider-agnostic AI layer** — the chat answering questions about
  me and the TL;DR block above both run on whichever API key exists,
  and the site survives having none
